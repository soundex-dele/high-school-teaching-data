# Teaching Data

面向 Agent Studio“学之有道”的版本化教学知识与原创题库。数据模型支持小学、初中、高中以及不同学科、年级和教材版本。

当前数据集覆盖：

- 现行湘教版高中数学：必修第一册、必修第二册、选择性必修第一册、选择性必修第二册。
- 现行普通高中历史统编教材（人民教育出版社）：《中外历史纲要》上、下册及三册选择性必修。

当前包含 54 个通用知识点、54 个教材映射、270 个详细知识项和 270 道原创题。

- 当前每个教材知识点关联 5 道四选一原创题，默认难度分布为 2 道基础、2 道中等、1 道提高。基础题也必须调用具体学科知识，不使用“最佳学习方法”一类元认知占位题。
- 每个知识点包含 5–15 个详细知识项。数学按概念、定义、公式、定理、性质、方法和模型组织；历史按概念、事件、过程、影响和比较组织。
- 数学公式使用 LaTeX；定理分别保存适用条件和结论，便于地图展示与后续审核。
- 详细知识项使用知识点文件内的稳定局部 ID；成熟后可以晋升为独立可出题知识点。

## 三层结构

    knowledge/                         通用知识层，不绑定出版社
      math/
      history/
    curricula/                         教材目录与教材知识点映射
      math/xj-current/
        catalog.yaml
        mappings/
    question_banks/                    独立题库，按学段和学科分片
      senior-high/
        math/
        history/

- 通用知识层使用 canonical_id，同一知识概念可供多个教材版本复用。
- 教材映射层保留面向产品的稳定知识点 ID，并记录学段、年级范围、学期、出版社章节和关联题库。
- 题库层独立保存题型、认知层级、推理步数、预计用时、审核状态和适用教材范围。
- 后端加载时组装三层数据，现有课程树和答题卡接口仍返回完整知识点及 questions。

## 增加学科或年级

1. 在 manifest.yaml 注册通用知识目录、题库目录和教材版本。
2. 在 knowledge/<subject>/ 创建通用知识点，使用不绑定出版社的稳定 ID。
3. 在 curricula/<subject>/<edition>/ 创建目录和映射，映射到通用知识点。
4. 在 question_banks/<stage>/<subject>/ 创建题库，并声明适用知识点、年级和教材范围。
5. 运行校验；题目先进入 draft 或 self_checked，学科审核后再提升状态。

## 校验

```bash
python scripts/validate.py
```

校验会检查三层 Schema、跨层引用、稳定 ID、学段年级范围、教材适用范围、详细知识项覆盖、LaTeX 花括号、题型答案、认知层级、难度分布、跨库重复题和元认知模板题，并输出覆盖率报告。

仓库内置 `.github/workflows/validate.yml`，每次推送和拉取请求都会自动执行相同校验。

## 内容原则

- 只保存原创知识摘要和原创题，不复制教材正文、例题或图片。
- 数学题应要求概念辨析、运算、条件判断或多步推理；历史题使用同章概念作干扰项，并通过具体史实、时空和因果线索作答。
- 干扰项必须在同一知识语境中具有迷惑性，不能依靠措辞长度、常识性褒贬或“总是/绝不”等绝对词直接排除。
- 解析不仅给出答案，还要说明关键条件、计算过程或材料线索。
- curriculum_id、教材知识点 id、通用知识点 canonical_id 和题目 id 都是稳定接口，不随显示名称调整。
- 详细知识项先经过 `self_checked`，涉及教材版本差异或表述争议的内容应升级为 `teacher_reviewed` 后再作为独立题卡知识点。
- 修改教材目录或题目后必须先通过校验。
